# Full Codebase Audit — 2026-07-27

Record of the audit that produced this documentation set. Scope: all research notes,
both prior knowledge-base documents, the complete `aurav2` source (36 files), and a
survey of the v1 codebase (18.5k lines).

**State at audit time:** v1 working and feature-rich but architecturally superseded.
v2 at Phase 1 + Phase 2A–2E, typecheck clean. Design thinking well ahead of the code —
but the documents had begun contradicting each other, and several contradictions were
load-bearing for the next phase.

Resolutions are recorded as D-16 … D-29 in [07-DECISIONS.md](07-DECISIONS.md).

## A · Architectural contradictions

| | Finding | Resolution |
|---|---|---|
| A1 | **Three mutually exclusive geometry systems specified**, none chosen: shared-topology icosphere (KB Constraint 2), 14 native Three geometries (brick registry §2), SDF raymarching (brick registry §3). `ShapeFactory.ts` was the next file to write and had three incompatible specs. | D-20 |
| A2 | **Modulation routing had no owner.** `VisualState.modulationConnectionIds` said connections belong to a state; `useModulationStore` held one flat global array. | D-24 |
| A3 | **`VisualState.sceneObjectIds` referenced a store that did not exist.** No `useSceneStore` in any store list or phase plan, despite the layer stack being the centre of the app. | Phase 3C |
| A4 | **Offline render was architecturally impossible.** `AudioDataBus` held only the current live value; the exporter renders out of order and faster than real time. Preview and export would have produced different videos. | D-21 |
| A5 | **`TargetParam` / `SourceMetric` were closed string unions** (18 shape params, 10 metrics) — could not express a light, a particle count, or any future brick, contradicting the Unified Field principle. | D-23 |
| A6 | **The dual camera was not dual.** One `PerspectiveCamera` with `makeDefault`; "preview" moved the render camera. `OrbitControls` and the WASD fly loop were both mounted, fighting over `camera.position` every frame. | D-26 |
| A7 | **Each page mounted its own `<Canvas>`** — every tab switch destroyed and rebuilt the WebGL context and all GPU resources. | D-25 |
| A8 | **Decisions made twice, differently.** Platform: "Tauri preferred" vs. "pure web SPA, desktop dropped entirely." Undo: "Command Pattern / zundo", then "Command Pattern over Zundo", while the registry listed `zundo` as the dependency. | D-19, D-28 |

## B · Design gaps

| | Finding | Resolution |
|---|---|---|
| B1 | **Nothing implemented the product's stated purpose.** "Story, tension, call and response" sat as an open question in every document. Two mechanisms were missing: musical state that persists over bars, and object-to-object reference. v1's section-aware intensity engine (`js/markers.js`) had been dropped from the v2 design entirely. | D-29 |
| B2 | **Solo-isolates-visuals was a side effect of the fader.** Analysis tapped post-gain, so lowering a stem's volume silently killed its visual reaction and muting killed visuals outright. | D-27 |
| B3 | **The 24 v1 modes were scheduled for port** into an architecture whose core principle says monolithic modes should not exist. ~2 weeks of work producing black boxes. | D-18 |
| B4 | **No single time authority.** Rack rAF clock, R3F `useFrame`, and an implied export clock. | D-22 |
| B5 | Long-open and still unresolved: primary/secondary shape relationship, camera extrapolation, lighting module (zero design), 2D overlay layer (zero design), lasers, image layers. | [08-OPEN-QUESTIONS.md](08-OPEN-QUESTIONS.md) |

## C · Code defects

All fixed 2026-07-27 (Phases 1H / 2F).

| | Location | Defect |
|---|---|---|
| C1 | `RealtimeAnalyser` | **Spectral centroid normalisation wrong.** Meyda returns a *bin index* (0…bufferSize/2), not Hz — verified against Meyda's source (`mu(1, ampSpectrum)`). Dividing by Nyquist produced ~0.005 permanently. |
| C2 | `RealtimeAnalyser` | **Band energies unusable.** Linear amplitudes averaged over unequal bin counts — `sub` spans ~1 bin, `brilliance` ~160. Sub pinned high, brilliance at zero. User-visible as *"nothing reacts to my hats."* |
| C3 | `AudioDataBus` | **Buffer aliasing.** `allocate()` reallocated the backing array while `getBands()` returned a `subarray` view into the old one. Any cached view silently read dead memory after the next import. |
| C4 | `MultiTrackRack` | `pause()` had no `isPlaying` guard — a second call added stale elapsed time and jumped the playhead forward. |
| C5 | `MultiTrackRack` | `getMaxDuration()` ignored trim bounds; playback ran past the trimmed project end. |
| C6 | `MultiTrackRack` | **Transport wrote `currentTime` to Zustand 60×/sec** — the exact re-render storm the architecture forbids. Every `TrackRow` and `WaveformCanvas` re-rendered every frame. |
| C7 | `WaveformCanvas` | Redrew the entire waveform bar-by-bar every frame to move a 1px playhead; draw effect had no dependency on the computed peaks. |
| C8 | `ShortcutManager` | **No modifier matching** — `Ctrl+S` fired the `KeyS` action. `Tab` binding called `preventDefault()` globally, breaking keyboard accessibility. `rebind()` mutated in place with no re-render and no persistence. |
| C9 | `DualCameraEngine` | Global `keydown` with no text-input guard — typing "wasd" in a text field flew the camera. |
| C10 | `TrackRow` | `setTimeout(…, 0)` to "wait for Zustand" — unnecessary, `set` is synchronous. |
| C11 | singletons | `DualCameraEngine` / `ShortcutManager` attached window listeners in `getInstance()`; `dispose()` never called. |
| C12 | `ViewportHUD` and others | `backdrop-blur-sm` despite the design system explicitly banning glassmorphism; raw hex in four files despite the "zero raw hex" rule. |
| C13 | `useUIStore` | Exiting immersive view force-expanded all docks, discarding the user's manual collapse state. |
| C14 | `package.json` | No `typecheck`, `test`, or `format` scripts; no test setup, despite the plan specifying Vitest verification. |

## Postscript — the invariant test paid for itself immediately

`proceduralMesh.test.ts` was written alongside the shared-topology factory and failed on
its first run. Two compounding errors in the base geometry:

1. Three.js `PolyhedronGeometry` splits each face into **`(detail+1)²`** triangles, not
   `4^detail` — the formula the original plan's "642-vertex icosphere" was derived from.
2. `mergeVertices()` welds on **all** attributes, so the UV seam kept a ring of
   coincident vertices apart and the weld was incomplete.

Together these produced a base mesh of **183 vertices instead of 642**. Nothing would
have looked wrong while authoring shapes. It would have surfaced in Phase 4F as
corrupted morphing — the exact failure mode HC-4 exists to prevent, discovered several
phases downstream of its cause.

This is the argument for writing the invariant test at the same time as the invariant,
rather than after the feature "works".
